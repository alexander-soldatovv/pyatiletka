# README_FIRST: как использовать этот пакет (для капитана)

Что внутри: полное ТЗ на продукт «Пятилетка» (бот + мини-приложение в MAX для человека за пять лет до пенсии) и набор промтов, по которым Claude Code делает проект, пока команда параллельно собирает данные, опрос и презентацию. Запасная концепция «Новосёл» (иногородний студент) лежит в `alt_novosel/` целиком.

## Что здесь проверено, а что нет (читать обязательно)

**Проверено 29.09.2026:**
- по dev.max.ru: домен API, авторизация, отправка сообщений и клавиатуры, long polling и вебхуки, мини-приложения, Bridge, алгоритм проверки initData, библиотека @maxhub/max-bot-api 0.3.1;
- расчёт пенсионного возраста в `starter/src/pension-age.js` **запускался**: 9 тестов зелёные (`cd starter && node --test`). Но тесты сверяют формулу только с **5 примерами из КонсультантПлюс** (мужчины 1962 и 1963, женщины 1965, 1967, 1968 г.р.).

**Прочитано, но только как пересказ инструмента (не дословно):** страницы КонсультантПлюс, СФР, mos.ru, Гарант про предпенсионный возраст, ст. 185.1 ТК, условия пенсии на 2026 год (15 лет стажа, 30 баллов), налоговые льготы. Дословную сверку с первоисточником делает Claude Code (промт P-SRC) или бизнес-аналитик.

**НЕ проверено:**
- **Полная таблица Приложения 6 к Закону № 400-ФЗ не получена.** Формула расчёта возраста выведена мной из переходной таблицы. Это главный юридический риск. Пока не сверена, все даты в продукте только «ориентировочные».
- Налоговые льготы: пересказы неоднозначны (нужно ли заявление), помечены как слабо подтверждённые.
- Возраст участников «Московского долголетия», региональные меры Татарстана, бесплатное обучение через центры занятости, Онлайнинспекция труда.
- **Пользуются ли люди 50-65 лет мессенджером MAX.** Это главное допущение проекта, данных у меня нет. Проверяется вашим опросом.
- Код в `starter/`, кроме `pension-age.js`, не тестировался (`webapp-auth.js`, `dates.js`, `config.js` из прошлой заготовки). Бот, сервер, мини-приложение, мок MAX, Docker, README пишет Claude Code.
- Docker-сборка не проверялась (в моей среде нет Docker-демона). Сертификат Минцифры не скачан (мой доступ к сайту закрыт): нужно скачать самим и положить в `certs/`.
- Точное время дедлайна и формат защиты в кейсе не указаны.

## Три шага прямо сейчас

1. **Ответьте на вопросы из ТЗ, раздел 16.** Самые срочные: ник бота (потом не поменять), где токен и можно ли задать URL мини-приложения (спросите организаторов), где хостим с HTTPS, кто скачивает сертификат Минцифры, **и решение №11: что делаем, если опрос не подтвердит проблему**.
2. **Запустите опрос сегодня.** Каждый участник команды опрашивает 5-8 человек 50-65 лет (родители, бабушки и дедушки, знакомые). Инструкция в `03_ОПРОС_И_ИНТЕРВЬЮ.md`. Ответы на вопросы про MAX и Госуслуги критичны.
3. **Запустите Claude Code:** распакуйте архив в пустую папку, откройте в ней Claude Code, вставьте блок из `01_MASTER_PROMPT.md`, затем идите по `02_PROMPTS_STAGES.md` (P0, P1, ...). **Параллельно** запустите P-SRC (раздел 13): сверка таблицы возраста с законом.

## Идеи для усиления (мнение автора, не проверенный факт)

- Режим «для родителя»: взрослый ребёнок настраивает карту и пересылает её. Он же закрывает риск «не пользуются MAX». Хорошо бы сделать его Must, если опрос покажет низкое пользование MAX у 50+.
- Второй региональный пакет Татарстан (финал в Казани): живой пример масштабирования, но только с проверенными фактами.
- Выход на кадровую службу любого работодателя, где у кого-то из команды есть контакт: письмо-намерение усилит слайд про пилот (называть его именно так).
- Запись 60-секундного видео демо на реальном MAX как запасной вариант для защиты.
- Простой контроль юриста: попросить любого юриста или знакомого кадровика прочитать тексты шагов и дисклеймеры за час.
