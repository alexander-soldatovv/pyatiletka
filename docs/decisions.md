# Технические решения

Дата: 29.09.2026.

## D1. Один сервис Node.js

Бот, внутренний HTTP API, мини-приложение и планировщик будут работать в одном процессе. Это сокращает число точек отказа и упрощает запуск для жюри. Код разделяется на независимые модули.

## D2. SQLite из стандартной библиотеки Node.js

Используется `node:sqlite`, без нативных npm-модулей. В доступной среде модуль запускается на Node.js 24.19.0. Минимальная версия проекта остаётся Node.js 22.13.0. Проверка внутри `node:22-slim` запланирована на этап Docker. В текущей среде Docker CLI установлен, но демон недоступен.

## D3. Таблица пенсионного возраста в данных

Упрощённая стартовая формула была неверна для людей, достигших прежнего пенсионного возраста в 2019 и 2020 годах: закон допускает назначение на 6 месяцев раньше возраста из Приложения 6. Расчёт переведён на параметры из `data/pension_age.json` и учитывает эту поправку.

## D4. Внутренний API не заявляется как собственный

API мини-приложения является частью одного продукта и не заявляется как отдельный публичный API. Это не создаёт дополнительные требования OpenAPI и DATA-API.yaml.

## D5. MAX API

На 29.09.2026 подтверждены новый домен `platform-api2.max.ru`, авторизация токеном в заголовке, необходимость сертификата Минцифры и рекомендация webhook для production. В changelog также указано, что `GET /chats` больше не поддерживается с июня 2026 года. Проект не будет использовать этот метод.

## D6. Библиотека MAX и обработчики бота

Проверены исходный код и типы установленной `@maxhub/max-bot-api` версии 0.3.1. Конструктор `Bot` принимает `clientOptions.baseUrl` и пользовательский `fetch`. События называются `bot_started`, `message_created`, `message_callback`. Для ответа на callback используется `ctx.answerOnCallback({ message })`. Команды библиотека регистрирует методом `bot.api.setMyCommands`, который вызывает `PATCH /me/commands`. Кнопки создаются через `Keyboard.button.callback`, `link`, `openApp` и `clipboard`.

У версии 0.3.1 есть особенность: сообщение только с вложением приходит с `body.text = null`, но middleware `command()` считает наличие такого поля текстовым сообщением. В проекте сообщения с нетекстовыми вложениями перехватываются до обработчиков команд.

Сверка: [официальный пример JavaScript](https://dev.max.ru/docs/chatbots/bots-coding/js), [клавиатуры](https://dev.max.ru/docs-api/use-cases/sending-messages/keyboard), а также код установленного пакета в `node_modules`.

## D7. Очередь и запасной переход в мини-приложение

Исходящие сообщения идут через очередь на диалог с интервалом 500 мс, то есть не более двух запусков отправки в секунду. Ответы 429 и 5xx повторяются не более трёх раз с экспоненциальной паузой. HTTP-запрос ограничен таймаутом 35 секунд, значение настраивается через `MAX_REQUEST_TIMEOUT_MS`.

Основной вариант запуска карты использует `open_app`. Если API отклоняет сообщение с этой кнопкой, бот повторяет то же сообщение с кнопкой `link` на `https://max.ru/<botName>?startapp=plan`. Формат диплинка подтверждён [документацией мини-приложений](https://dev.max.ru/docs/webapps/introduction). Поведение `open_app` без URL, заданного в настройках реального бота, документацией однозначно не описано и остаётся допущением A3.

Локальный mock реализует актуальные `/me`, `/updates`, `/messages`, `/answers`, `/subscriptions`, `/me/commands`. Для удалённого в июне 2026 года `GET /chats` mock возвращает 410, чтобы тесты не закрепляли устаревший API.

## D8. Ванильный HTML, CSS и JavaScript вместо MAX UI

Официальный MAX UI существует как пакет `@maxhub/max-ui`, требует React 18+ и собственную сборку. На P3 выбран интерфейс без React и без сборщика: три статических файла раздаются тем же процессом Node.js. Это сохраняет нулевую стоимость сборки фронтенда, не добавляет зависимости и нативные модули, а также уменьшает Docker-образ. Совместимость с MAX обеспечивается официальным Bridge, mobile-first вёрсткой, светлой и тёмной темами и доступными контролами. Решение можно пересмотреть после пилота, если потребуется полное визуальное соответствие дизайн-системе MAX.

Источники: [MAX UI](https://dev.max.ru/ui), [подключение мини-приложения](https://dev.max.ru/docs/webapps/introduction).

## D9. Один HTTP-сервер для Web App и webhook

Статика, внутренний API, `/healthz` и callback webhook обслуживаются одним `node:http` сервером. Это убирает CORS, оставляет единый origin для мини-приложения и не создаёт второй слушающий порт. В polling-режиме тот же сервер продолжает раздавать Web App и API.
