# Отчёт P6: подготовка проверки реального MAX

Дата: 30.09.2026.

## Сделано автоматически

- Повторно сверены актуальные официальные страницы MAX: API changelog, `GET /me`, webhook, Mini App, Bridge и клавиатуры.
- Подтверждены `platform-api2.max.ru`, заголовок `Authorization`, webhook `X-Max-Bot-Api-Secret`, HTTPS на 443 и рекомендация webhook для production.
- Конфигурация webhook теперь отклоняет HTTP, нестандартный порт, небезопасный путь и секрет вне разрешённого алфавита.
- Добавлен `scripts/smoke-real.js`: read-only preflight по умолчанию; отправка, webhook и контейнер требуют явных флагов.
- Добавлена серверная P6-диагностика ID из проверенного `initData` и запуск по `startapp=smoke`.
- Для web/desktop добавлен актуальный `shareMaxContent` перед link-fallback.
- Без токена проверены CA bundle, payload `open_app`/`clipboard` и TLS к MAX: ожидаемый HTTP 401.
- Полная регрессия после изменений: 115/115 тестов, `check:data` и `check:secrets` успешно.

## Статус A1-A10

A2, A4-A6, A8 и A9 имеют автоматическое или mock-покрытие, но остаются `частично` до реального клиента. A1, A3, A7 и A10 требуют человека. Полная таблица находится в `docs/assumptions.md`.

## Блокеры

В рабочей папке нет `.env`, поэтому действующий токен, `GET /me` с авторизацией и отправка владельцу не выполнялись. Также недоступен Docker daemon. Проверки iOS, Android и web нельзя честно закрыть без действий пользователя в MAX.

Следующий шаг: заполнить только локальный `.env`, запустить `npm run smoke:real`, затем пройти `scripts/smoke-real.md`. Секреты не копируются в отчёт.
