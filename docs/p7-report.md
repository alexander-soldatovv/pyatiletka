# Отчёт P7: ревью безопасности и качества

Дата: 30.09.2026.

Ревью выполнено adversarial-проходом по коду, тестам, истории Git, данным, README и критериям страниц 9-15 `docs/case.pdf`. Эта сессия участвовала в разработке, поэтому проверка не называется организационно независимой. Для настоящего независимого мнения перед сдачей нужен второй человек или отдельная чистая сессия.

| Приоритет | Проблема | Исходный вердикт | Результат |

| 4 | публичный `/healthz` раскрывал внутренние счётчики использования | замечание | исправлено; endpoint возвращает только готовность компонентов |

## Вердикты по проверкам

| Пункт | Вердикт после исправлений | Где и как проверено |
|---|---|---|
| Секреты в файлах и истории | ОК | `scripts/check-secrets.js`, `git log -p`; токены и приватные ключи не найдены |
| `.env`, `.dockerignore`, Docker secrets | ОК | `.env` игнорируется Git и build context; example содержит пустые секреты |
| `initData` | ОК | `src/webapp-auth.js`; официальный HMAC `WebAppData`, единственный hash, уникальные ключи, URL decode, свежесть, user ID, timing-safe compare; негативные тесты |
| Demo auth | ОК | выключен по умолчанию в `.env.example`; требует явного server flag |
| IDOR и SQL injection | ОК | user ID только из подписанного `initData`; API не принимает чужой ID; SQL параметризован |
| XSS, CSP, headers, body/rate limits | ОК | динамический HTML экранируется; CSP, HSTS, no-sniff, body limit, timeouts и per-user rate limit покрыты тестами |
| Удаление данных | ОК | транзакционный cascade удаляет профиль, задачи, напоминания и события; bot/API e2e проверяют нулевой остаток |
| Логи и аналитика | ОК | ошибки логируются без message/stack/ID; статистика агрегирована и защищена `ADMIN_TOKEN` |
| Неожиданные апдейты | ОК | вложения без текста, неизвестные и старые callback, пустые состояния покрыты e2e |
| Повторные действия | ОК для одной реплики | статусы идемпотентны, очередь на диалог, уникальные резервы; multi-replica вне MVP |
| 429, 5xx, сеть | ОК | ограниченные повторы, backoff, timeout, reconnect и изоляция ошибок покрыты тестами |
| Битые правила и БД | ОК с ограничением | схема данных проверяется до запуска; healthcheck видит БД; автоматического восстановления БД нет |
| Юридическая честность | ОК с известными ограничениями | source/checked/basis обязательны; досрочные пенсии не рассчитываются; модельные региональные данные помечены |
| Медицинская честность | ОК | нет диагноза и интерпретации; диспансеризация сопровождается безопасной оговоркой |
| README по требованиям кейса | ОК | назначение, сценарий, архитектура, Docker-команда, env, порты, зависимости, данные, mock, проверка, ограничения и рестарт присутствуют |
| Зависимости | ОК на дату ревью | точные версии в lockfile; 26 пакетов exact-графа проверены OSV, известных записей не найдено |
| U+2014, TODO, мусор | ОК | проверки данных и поиск по исходникам; временные файлы находятся в игнорируемом `tmp/` |

## Проверено

- `scripts/check-data.js`: успешно.
- `scripts/check-secrets.js`: успешно.
- `node --test`: 116 из 116 тестов успешно.
- OSV query batch: 26 пакетов, 0 известных записей на момент проверки.
- Актуальная документация MAX подтверждает используемый алгоритм подписи и рекомендуемую свежесть `auth_date` в один час.

## Не проверено

- Реальный MAX, доставка и Bridge на iOS, Android, desktop и web без токена.
- Docker build/history/healthcheck без Docker daemon.
- Независимое ревью вторым человеком.
- Production-соответствие ФЗ-152: оператор, основание обработки, срок хранения, уведомление и регламент резервных копий должны быть определены до пилота.
