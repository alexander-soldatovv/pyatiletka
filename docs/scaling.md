# Масштабирование: новый регион за один рабочий день

Дата: 30.09.2026.

## Что остаётся неизменным

Диалог из пяти вопросов, расчёт общеустановленного возраста, модель задач, интерфейс карты, отметки, напоминания, безопасность `initData`, SQLite-схема и MAX-интеграция не зависят от региона.

## Что адаптируется

Региональные меры, названия организаций, каналы обращения, документы, сроки, нормативные основания, дата проверки и иногда применимость шага. Эти сведения находятся в `data/regions.json` или в новой задаче `data/rules.json`, а не в обработчиках.

## Процедура

1. Владелец регионального пакета выбирает один субъект и одного ответственного редактора.
2. Аналитик собирает факты только из сайтов органа власти, региональной соцзащиты и официальных нормативных актов. Для каждого факта фиксирует URL, территорию, дату действия и дату проверки.
3. Юрист или назначенный факт-чекер сверяет формулировку с первоисточником. Непроверенное утверждение получает `basis: model` и явный текст уточнения.
4. Разработчик добавляет объект региона в `data/regions.json`; общую меру добавляет в `data/rules.json`, региональное отличие - в `task_overrides`.
5. Редактор добавляет каждое новое утверждение в `docs/provenance.md` и проверяет, что в интерфейсе видны источник и дата.
6. Команда выполняет `npm run check:data`, `npm test` и `npm run check:secrets`.
7. Представитель региона проходит сценарий для минимум трёх профилей: до окна, в окне, после ориентировочной даты. Отдельно проверяются досрочное основание и неработающий пользователь.
8. После ревью создаётся commit, образ развёртывается на тестовом боте, затем на production. Версия `regions.json` увеличивается.

## План на день

| Время | Результат | Владелец |
|---|---|---|
| 09:00-11:00 | Реестр официальных источников и границы пакета | Региональный аналитик |
| 11:00-13:00 | Проверенные формулировки и применимость | Факт-чекер/юрист |
| 13:00-15:00 | JSON-пакет и provenance | Разработчик + аналитик |
| 15:00-17:00 | Автотесты и пользовательский прогон | QA + представитель региона |
| 17:00-18:00 | Ревью, версия, тестовый deploy | Техлид |

Срок в один день реалистичен только для малого пакета из 1-3 мер с доступными первоисточниками. Сложные муниципальные различия требуют отдельного цикла.

## Владельцы и регламент

| Объект | Владелец | Периодичность |
|---|---|---|
| Федеральные пенсионные правила | Юридический факт-чекер | Ежемесячная проверка и внепланово после изменения закона |
| Региональный пакет | Назначенный аналитик субъекта | Ежеквартально и перед каждым релизом |
| MAX API и Bridge | Техлид | Перед релизом и после changelog MAX |
| Тексты простым языком | Продукт + UX-редактор | При каждом изменении факта |
| Автотесты и schema check | Разработчик/QA | В каждом commit |

Просроченный факт не удаляется молча: пакет переводится в модельный статус, а пользователь видит просьбу уточнить условие в ведомстве. Изменение, влияющее на рассчитанную дату, требует новой версии данных, регрессионных векторов и записи в release notes.

## Порядок тиражирования

После Москвы первый пакет логично проверить в Татарстане: финал проходит в Казани и доступен локальный представитель для проверки. Затем выбираются 2-3 региона с различающимися мерами. Только после подтверждения процесса обновления расширяется число субъектов. Главные риски - устаревшие нормы, разные муниципальные условия, отсутствие владельца данных и обещание права без официального подтверждения.
