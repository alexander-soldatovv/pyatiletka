# P6: проверка реального MAX

Дата подготовки: 30.09.2026. Не вставляйте токен, webhook-секрет или содержимое `.env` в этот файл, issue, чат или скриншот.

## Перед началом

- Развёрнут текущий commit на публичном HTTPS.
- В `.env` заполнены `BOT_TOKEN`, `BOT_USERNAME`, `EVENT_SALT`, `ADMIN_TOKEN`.
- Для webhook заполнены `BOT_MODE=webhook`, `PUBLIC_BASE_URL`, `WEBHOOK_PATH`, `WEBHOOK_SECRET`.
- URL Mini App пока не задавайте, если нужно проверить A3 `до настройки`.
- Откройте бота, нажмите Start и выполните `/id`. Запишите ID только в локальный `SMOKE_USER_ID` файла `.env`.
- Не запускайте приложение одновременно в polling и webhook: MAX поддерживает один механизм получения событий.

Безопасный read-only preflight:

```bash
npm run smoke:real
```

Скрипт не выводит токен или `SMOKE_USER_ID`. Он проверяет CA, payload кнопок, `GET /me` и список webhook-подписок. Мутации выполняются только с явными флагами.

## P6-карточка

После `bot_started` и `/id` отправьте себе проверочную карточку:

```bash
npm run smoke:real -- --send
```

Команда проверяет A8 на уровне реального API и создаёт две кнопки: `open_app` со `startapp=smoke` и `clipboard`. Она не отправляет сообщения другим пользователям.

## Webhook A6

1. Запустите production-конфигурацию с `BOT_MODE=webhook` и публичным HTTPS на 443.
2. Проверьте подписку и healthcheck:

   ```bash
   npm run smoke:real -- --webhook
   ```

3. Отправьте `/id` в MAX.
4. В логах должен появиться штатный ответ без `webhook_fallback_to_polling`, токена, имени пользователя или исходного user ID.
5. Запрос на `/webhook` без `X-Max-Bot-Api-Secret` должен получать 404; это также покрыто автотестом.

| Публичный `/healthz` здоров | | |
| MAX содержит точный webhook URL | | |
| Реальный update обработан | | |
| В логах нет секрета и ПД | | |

## Напоминания и `bot_stopped`

Для теста используйте отдельного пользователя и временную конфигурацию на тестовом стенде. Не меняйте production-даты без согласования.

1. После `bot_started` запустите `--send` и подтвердите доставку без нового сообщения от пользователя.
2. Остановите бота в MAX, дождитесь события `bot_stopped` и убедитесь, что `bot_active=0` косвенно: следующий контролируемый проход не доставляет напоминание.
3. Снова запустите бота, проверьте восстановление `bot_active` и единственную доставку без дубля.
